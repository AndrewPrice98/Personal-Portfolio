Military Flight Tracker

Priority: Medium Web development, open-source intelligence React, Leaflet, axios, ADS-B and NASA EONET APIs

Summary

Military Flight Tracker is a live map of military aircraft built at a React hackathon. It polls ADS-B data every 10 seconds, draws flight trails, raises alerts for emergency squawks and notable airframes, and overlays NASA natural events and conflict zones.

Problem

ADS-B data is public, but a raw list of aircraft is just rows. I wanted it to read the way an analyst would: what is flying right now, which aircraft are worth a second look, and what is happening on the ground near them. The work was choosing signals worth surfacing and wiring several public sources together on one map.

What I built

  • A live map of aircraft from api.adsb.lol/v2/mil, refreshed every 10 seconds, with a flight trail per aircraft.
  • Alert watch. Emergency squawks 7500 (hijack), 7600 (radio failure) and 7700 (general emergency) sort to the top. A watch list of 12 ICAO type codes flags notable airframes, such as the E-4 airborne command post, the B-2 stealth bomber, the E-6 nuclear command relay and the U-2.
  • A squawk reference that decodes special codes and military blocks.
  • Aircraft detail. A dataset of 129 U.S. military aircraft with photos, matched by ICAO type code with an alias table, and the country inferred from the ICAO hex range.
  • Position source. Each aircraft is labelled by how its position is known (ADS-B broadcast, or tracked without self-reported position, like MLAT and TIS-B).
  • Context layers. NASA EONET natural events (open events from the last 10 days, refreshed every 10 minutes) and 15 hand-written conflict zones, each a circle with a start year and a note.

How it works

  • A useMilitaryFeed hook polls the endpoint on an interval and keeps the last 8 positions per aircraft, keyed by hex code. A point is only added when the aircraft actually moved, and aircraft without a position are skipped.
  • findAlerts checks each aircraft's squawk against the emergency codes first, then its type against the watch list.
  • The CORS wall. adsb.lol sends no CORS headers, so a browser refuses to read its responses. In development the Vite dev server proxies /api/adb to it instead.

Evidence

  • It was built at the hackathon. The repository holds the full source, including a written walkthrough of importing an API into a React app, using this feed as the worked example.
  • No screenshot or live link: the app depends on the dev-server proxy above, so there is no deployed copy to point at.

What I'd do next

  • A real proxy. The CORS workaround exists only in npm run dev. A small serverless function would let it deploy.
  • Longer trails. Eight positions is about 80 seconds of history at a 10-second poll, if the aircraft moves on every update.
