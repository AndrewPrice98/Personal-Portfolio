Job Tracker

MED Featured: supporting Web development, email integration React, Node, Vercel functions, Microsoft Graph (MSAL), IMAP

Summary

Job Tracker is a job-search organizer that reads your inbox. It signs in to Gmail over IMAP through a Vercel serverless function, or to Outlook through Microsoft Graph with MSAL sign-in, finds the emails about your own applications, classifies each one's stage, pulls out the role, interview time and salary, and builds a pipeline per company. It also has an interview calendar, side-by-side offer comparison, a STAR story bank and LinkedIn import. This one is code only: its Vercel deployment no longer exists.

Problem

A job search scatters its state across an inbox: confirmations, assessments, interview invites, offers and rejections, mixed in with job-board alerts and newsletters. Keeping a spreadsheet by hand falls behind. I wanted it to read the mail, but handling someone's mailbox credentials is the part a tool like this must get right, so the design is built around not holding them.

What I built

  • Two inbox connectors. Gmail with an app password the user creates in their own Google account (no developer registration). Outlook through Microsoft sign-in, because Microsoft has turned off app passwords for mail apps.
  • A matcher that decides whether an email is about one of your own applications, using a keyword file.
  • A stage classifier with six stages: application received, assessment, interview, offer, rejection, and withdrawn or closed.
  • Detail extraction: role and company, interview time, assessment deadline and salary on offers.
  • A pipeline per company, an interview calendar, offer comparison, a STAR story bank, LinkedIn import and a resume box.
  • Backups. Everything is stored in the visitor's own browser, with Your data, Export backup to move or back it up.

How it works

  • Gmail path. The serverless function api/scan-email.js connects over IMAP with imapflow, scans All Mail, and looks back at most 180 days. A cheap pass reads headers only (up to 3,000 envelopes) to pick likely job emails. A full pass then downloads the newest candidates, at most 150 per scan, and parses them. The credential is used once and never stored.
  • Outlook path. The browser signs in with MSAL and reads mail through Microsoft Graph with the delegated Mail.Read permission. It is a single-page-app registration with no client secret.
  • Matching rules. Subjects matching an exclude phrase (alerts, newsletters) are dropped. A phrase is strong when it names the application itself, or weak when it is generic. An email needs at least one strong phrase and a job-related word, so a credit card application does not count, and it must reach a score threshold. Applicant-tracking-system senders add weight, while job boards, which mostly send alerts, need more evidence. The same rules serve both Gmail and Outlook scans.
  • Stage ties. When an email matches several stages equally, the later stage wins.
  • Refresh. While the app is open, each connected inbox is checked every 30 minutes, fetching only mail newer than the last scan. There is no background checking while the site is closed, because that would need a server holding users' mail credentials.

Evidence

  • The repository ships a SETUP.md that walks through the Azure app registration, the Vercel deployment, and the manifest fix for personal-account sign-in errors.
  • The classifier reads the same job-application-keywords.json in the browser and in the serverless function, so there is one set of rules to tune.
  • The honest limit: this page has no live demo or screenshot, because the Vercel deployment is gone. The code is the evidence.

What I'd do next

  • Rate-limit the scan endpoint. The setup guide already calls for a Vercel Firewall rule on /api/scan-email, because without one anyone could use that endpoint to test stolen Gmail passwords. I would build the limit into the function instead of leaving it as an operator step.
  • Account coverage. Some accounts cannot create app passwords at all, for example many work or school accounts and accounts with Advanced Protection, and some companies block employees from approving apps themselves.
  • Outlook sign-in time. Microsoft limits how long a browser app can stay signed in, so Outlook refreshes on its own for only about a day before asking the user to sign in again.
